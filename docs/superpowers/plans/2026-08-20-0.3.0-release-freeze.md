# 0.3.0 Release Freeze Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Date 0.3.0 in changelog and support docs, land that freeze on `origin/main`, then create annotated `v0.3.0` and construct `rc-built` artifacts — without publishing or moving `v0.2.0`.

**Architecture:** Two trains. Train A is document and test-marker edits only. Train B is git tag plus `ci/check-release-candidate.sh` after the freeze commit exists on `origin/main` (GitHub rebase-merge rewrites SHAs, so never tag a pre-merge branch commit).

**Tech Stack:** Git, Keep a Changelog, existing `tests/release_documents.rs` markers, `ci/check-release-candidate.sh`.

## Global Constraints

- Do not retarget, move, or delete annotated tag `v0.2.0` (`c7075b75d7460327d741814a15ff28fa1c1ec478`).
- Do not `cargo publish`. Do not store `CARGO_REGISTRY_TOKEN` in GitHub Actions.
- Do not change adapter, crypto, `Cargo.toml` version, API snapshots, or policy document versions (all stay 2).
- Do not rewrite `tests/release_candidate.sh` fixture `tag v0.2.0`.
- Changelog date is `2026-08-20`. Keep `## [0.2.0] - 2026-08-19` unchanged.
- Push tag `v0.3.0` only when the owner asks. Create it locally in Train B.
- `cargo fmt --all -- --check` must pass before every commit.

### Task 2: Annotated `v0.3.0` and `rc-built`

**Files:**
- None in the tree. Git tag plus artifacts outside the repository.

**Interfaces:**
- Consumes: Task 1 freeze commit as it exists on `origin/main` after merge (not the pre-merge branch SHA).
- Produces: annotated `v0.3.0`; `rc-built` directory outside the repo.

- [ ] **Step 1: Confirm the freeze is on `origin/main`**

```bash
git fetch origin
git checkout main
git merge --ff-only origin/main
git log -1 --oneline
git grep -n 'current tagged line' README.md
git rev-list -n 1 v0.2.0
```

Expected: HEAD is the freeze (or a rebase of it) on `origin/main`; README contains `current tagged line (\`v0.3.0\`)`; `v0.2.0` is still `c7075b75d7460327d741814a15ff28fa1c1ec478`. If `origin/main` has not merged Task 1, STOP.

- [ ] **Step 2: Create the annotated tag on that commit**

```bash
git tag -a v0.3.0 -m "$(cat <<'EOF'
gmcrypto-envelope-lite 0.3.0

Tagged 0.3.0 line. v0.2.0 remains the first crates.io candidate.
This tag is not a crates.io publication.
EOF
)"
git rev-list -n 1 v0.3.0
git rev-list -n 1 v0.2.0
```

Expected: `v0.3.0` equals `HEAD` / `origin/main`; `v0.2.0` unchanged. Do not `git push --tags`. Do not `git push origin v0.3.0` unless the owner asks.

- [ ] **Step 3: Construct `rc-built` outside the repository**

```bash
git status --short
out="${TMPDIR:-/tmp}/gmcrypto-envelope-lite-0.3.0-rc"
rm -rf "$out"
./ci/check-release-candidate.sh "$(git rev-parse HEAD)" "$out"
python3 -c 'import json,sys; m=json.load(open(sys.argv[1])); print(m["promotion_state"], m["version"])' "$out/rc-manifest.json"
```

Expected: empty `git status --short`; printed line `rc-built 0.3.0`.

If the command fails, do not move the tag; delete `v0.3.0` only if it was created on a broken tree, then fix Train A. Do not commit anything under `$out`.

- [ ] **Step 4: Record results in the task report**

Write freeze SHA, `v0.3.0` SHA, `v0.2.0` SHA, RC output path, and whether the tag was pushed (must be no unless asked). No repository commit in this task unless a freeze bugfix is required.
