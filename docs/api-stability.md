# Public API Stability

**Policy version:** 2

`gmcrypto-envelope-lite` follows Semantic Versioning. Within 0.3.x, patch releases do not intentionally break the checked-in public API snapshot. An intentional breaking change advances the minor version and is documented.

## Extensible public enums

`AuthenticationMode`, `AdapterErrorKind`, `KeyKind`, `PeerKeySource`, `Error`, and the feature-gated `EnvelopeMode` and `AeadAlgorithm` are `#[non_exhaustive]`. Downstream matches must include a fallback so new modes or redacted categories can be added without implying that old callers understand them.

## Intentionally closed enum

`CipherLocation` is exhaustive: `HeaderProtocolAdapter` supports only body or named-header placement. A different wire model uses a custom `ProtocolAdapter` rather than another built-in location.

## Public structures

Configuration, identity, key, header, context, and transport structures keep validation-relevant fields private. `SecureEnvelope` retains three public encoded fields because external `ProtocolAdapter` implementations must map them without access to plaintext or keys.

## Extension trait

`ProtocolAdapter` is deliberately object-safe, unsealed, `Send + Sync`, and implemented outside the crate. Adding a required trait method is therefore breaking; future additive behavior must use a default method or a new trait/version.

## Compatibility conveniences

Legacy authentication and shared key roles require explicitly named constructors or builder calls. They remain public for deployed wire compatibility and carry nearby security documentation. They are not defaults and are not recommendations for new protocol design.

## Baseline

The canonical 0.3.0 snapshots are `api/gmcrypto-envelope-lite-0.3.0.txt` (default features) and `api/gmcrypto-envelope-lite-0.3.0-aead.txt` (`--features aead`), generated by the pinned `cargo-public-api` version in `ci/tool-versions.sh` with simplified level two and color disabled. This level omits blanket and auto-trait noise while retaining derived public trait implementations, which remain part of the tracked semver surface. Both 0.3.0 snapshots include `HeaderSchemaBuilder::context_bound_authentication` and are not content-identical to their 0.2.0 counterparts.
