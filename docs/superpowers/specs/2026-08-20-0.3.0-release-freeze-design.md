# 0.3.0 Release Freeze Design

**Status:** Approved 2026-08-20 (approach A: freeze, tag, `rc-built`; no crates.io publish)

**Date:** 2026-08-20

**Target repository:** this repository (`gmcrypto-envelope-lite`)

**Target version:** 0.3.0 (already the crate identity on `main`)

## 1. Purpose

Cut the current `main` line as a **tagged 0.3.0 release freeze**: date the changelog, retarget release-status and support-table prose, create annotated `v0.3.0` after that freeze is on `origin/main`, and construct the repository-owned `rc-built` artifact set.

This phase does **not** add adapter or crypto behavior. It does **not** `cargo publish`. It does **not** retarget, move, or delete annotated `v0.2.0`.

## 2. Current baseline

Facts verified 2026-08-20 against `origin/main` `9516b12380a08b994cc24108ad7b4c76c1e384e0` (PR #15 rebase-merge) and annotated `v0.2.0` (`c7075b75d7460327d741814a15ff28fa1c1ec478`):

- `Cargo.toml` `version = "0.3.0"`. Both API snapshots exist at `api/gmcrypto-envelope-lite-0.3.0.txt` and `-aead.txt` and include `HeaderSchemaBuilder::context_bound_authentication`.
- `CHANGELOG.md` still has `## [Unreleased]` holding the 0.3.0 identity move and ContextBound adapter bullets. There is no dated `## [0.3.0]` heading. The 0.3.0 identity spec forbade that heading until the version is actually released.
- `README.md` §Release status: “Version 0.3.0 is unreleased and in development on `main`.” 0.2.0 is the tagged first crates.io *candidate*. Publication has not occurred.
- `SECURITY.md`: `| 0.3.x | Unreleased (\`main\`) |` and `| 0.2.x | Yes |`. `tests/release_documents.rs` pins those two rows.
- `RELEASE_CHECKLIST.md` title is already `# 0.3.0 Release Candidate External Gate Checklist`. Template version 2. Blank template only.
- Policy document versions remain 2 (security model, API-stability, engineering evidence, crypto inventory, checklist).
- The crate is **not** on crates.io. Live 0.2.0 publish was delayed. When 0.2.0 is published it is from `git checkout v0.2.0`, not from later `main`.
- GitHub rebase-merged PR #15, so original local SHAs (`848feb8` and parents) are not ancestors of `origin/main`. Tags must name commits that exist on `origin/main`.

## 3. Goals

- Record 0.3.0 as a dated Keep a Changelog release on `main`.
- Describe 0.3.0 as the current tagged line without claiming crates.io publication.
- Keep 0.2.0 as the tagged first crates.io candidate; keep `v0.2.0` at `c7075b75d7460327d741814a15ff28fa1c1ec478`.
- After the freeze commit is on `origin/main`, create annotated tag `v0.3.0` pointing at that commit.
- Run `ci/check-release-candidate.sh` against that tagged commit and store artifacts **outside** the repository. Do not commit RC tarballs or checksums.
- Update `tests/release_documents.rs` so CI matches the new support-table and release-status wording.

## 4. Non-goals

- `cargo publish` of 0.2.0 or 0.3.0.
- Storing `CARGO_REGISTRY_TOKEN` in GitHub Actions.
- Opening 0.4.0 identity, or adding a `| 0.4.x | Unreleased |` row.
- SM4-CCM, replay helpers, streaming, server-side APIs, charter min-and-newest `gmcrypto-core` CI, ContextBound fuzz schema switch.
- The deferred 0.3.0 test nits (extra collision slots, extra whitespace cases, direct `open()` mismatch assertion).
- Regenerating public-API snapshots, bumping policy **document** versions, or changing `ProtocolAdapter` / envelope crypto.
- Completing external checklist gates (`rc-approved`, `release-authorized`) in-tree.

## 5. Document freeze

One commit (or a tight pair: failing test then docs) with no production Rust behavior change.

### 5.1 Changelog

Keep an empty Unreleased section. Date the existing bullets:

```markdown
## [Unreleased]

## [0.3.0] - 2026-08-20

### Changed

- Version identity moved to 0.3.0. The tagged 0.2.0 line is unchanged. Both 0.3.0 public API snapshots include `HeaderSchemaBuilder::context_bound_authentication` and are not content-identical to their 0.2.0 counterparts.

### Added

- `HeaderSchemaBuilder::context_bound_authentication()` as an exclusive alternative to `.legacy_authentication()`. `HeaderProtocolAdapter` then signs crate-owned version-1 context bytes: request `0x01 || 0x01 || u64be(operation_len) || operation || u64be(request_id_len) || request_id`, response `0x01 || 0x02 || u64be(request_id_len) || request_id` from the echoed request-id header. Surrounding whitespace is rejected. Distinct `(operation, request_id)` pairs that collided under ASCII concatenation encode differently. `ProtocolAdapter` is unchanged.
```

Keep `## [0.2.0] - 2026-08-19` historical and unchanged. Do not invent comparison URL footnotes; this file has none today.

## 6. Integration and tag

GitHub rebase-merged the 0.3.0 adapter PR. Therefore:

1. Land the freeze via a pull request into `main` (do not push the freeze only as a local tag on a rewritten SHA). The freeze commit's README names `v0.3.0`; Train B MUST create that tag on the same `origin/main` commit immediately after merge so `main` is not left claiming a missing tag.
2. After `origin/main` contains the freeze (tree and commit recorded), create an **annotated** tag:
   - Name: `v0.3.0`
   - Target: that `origin/main` commit
   - Message:

     ```
     gmcrypto-envelope-lite 0.3.0

     Tagged 0.3.0 line. v0.2.0 remains the first crates.io candidate.
     This tag is not a crates.io publication.
     ```

3. Do not retarget `v0.2.0`. Verify `git rev-list -n 1 v0.2.0` is still `c7075b75d7460327d741814a15ff28fa1c1ec478` after every tag operation.
4. Push tag `v0.3.0` only when the owner asks. Creating the tag locally is part of this phase; pushing it is a separate owner action (same discipline as not publishing).

## 7. `rc-built`

After the freeze commit is known:

```sh
git status --short   # must be empty
./ci/check-release-candidate.sh <freeze-commit> /absolute/path/outside-this-repository/gmcrypto-envelope-lite-0.3.0-rc
```

Expected: promotion state `rc-built` in `rc-manifest.json`; package version `0.3.0`. Artifacts stay outside the checkout. Completing the blank `RELEASE_CHECKLIST.md` copy is an external owner record, not a repository commit.

If the RC command fails, fix the freeze (return to candidate-source); do not tag a failing tree.

## 8. Sequencing

Two trains. Do not mix the document freeze with the tag in one commit.

1. **Train A — freeze documents and tests** (PR).
2. **Train B — annotated `v0.3.0` + RC construction** after Train A is on `origin/main`.

## 9. Out of scope reminders

- Publish 0.2.0 from `v0.2.0` when a token with publish rights exists: `git checkout v0.2.0 && cargo publish --locked`.
- Publish 0.3.0 only from `v0.3.0` after external checklist gates, never from a later `main` that has moved to 0.4.0 identity.
